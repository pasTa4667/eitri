# Bounded live native fixture read

The operator approves one read-only, controller-scoped fixture-source tool on the live native path, one bounded genuine run, tests and five-axis review, then a stop. This is not production selection or M4 acceptance.

## Contract

- Separate exact opt-in: `npm run test:pi-native-read -- --run`. Help performs no profile, fixture, database or inference work. The existing random-string native probe remains unchanged.
- Exactly two model requests and one `read_fixture({})` on success. The native tool exists only when a trusted controller caller supplies its callback; production main does not. Existing tool admission, deadlines, accounting, durable result and Pause/reopen/Continue remain authoritative.
- The callback captures only `src/lib/errors.js` from the fixed sibling `eitri-test-web-app`, using the existing regular-file, no-symlink/single-link and quiescent-directory capture boundary. No model/CLI path or arbitrary filesystem tool is accepted. Reject empty, invalid UTF-8 or greater-than-4096-byte source. Source is data, never imported or executed.
- Only after admitted tool execution, send that captured source, virtual path and SHA-256 in the correlated tool result to the approved Pi-owned Codex route. The second response must contain only the exact SHA-256. This verifies delivery, not diagnosis, tests, remediation or a Git revision. Provenance is an uncommitted detached capture, not a controller worktree/check receipt.
- Request Pause after capture; verify the complete tool result in native SQLite, close/reopen, explicitly Continue with unchanged counters, verify the second response and final no-redispatch reopen, then remove only the successful generated store. Failure retains private data without retry, resume, lease repair or sign-in.
- Retain existing private dedicated-profile/sole-process lease, finite diagnostics, event validation, helper disposal before receipt, 60-second helper and 120/125-second command/backstop bounds. No credentials/raw source/model output in command output or checked-in evidence.
- No source edits, code execution, worker, Sentry/GitHub mutation, publication, auth changes, dependency changes or production enablement. The original demonstration checkout is read-only. Real refresh/crash recovery and general source-tool integration remain separate gates.

## Verification

New behavior must fail before implementation, then pass with synthetic profiles/intercepted HTTP over the actual live helper/native path. Cover exact tool/result correlation, unsupported tools/arguments/results, capture refusal, cancellation, default-disabled tools and opt-in launcher behavior. Run full `npm run verify:all` and `/skill:review` before the single genuine run. Record its finite verdict/exit without retry; a failed attempt does not imply OAuth rejection or successful live fixture-read acceptance.
