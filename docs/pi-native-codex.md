# Offline built-in Codex/native composition

The operator separately approves this offline-only slice after the standalone [controlled tool-use probe](pi-controlled-turn.md). It composes the installed ModelRuntime 1.4.0 **unmodified built-in Codex SSE path** with controller admissions, Pi Durable 1.3.0's native tool loop and real temporary SQLite. It is not a live adapter or M4 acceptance. See the [five-axis author review](evidence/pi-runtime/native-codex-review.md).

## Run

```sh
node --test test/pi-native-codex.test.mjs
```

All eight checks are offline. The existing `streamNativeFixture` selects a fixed synthetic Codex child only for trusted test fixture names. It refuses file-profile configuration **before** opening/claiming a profile. No command, production configuration or model output selects this path.

Each child receives one validated, action/epoch-correlated native context. It starts in the existing generated empty HOME/cwd with a minimal environment, verifies installed source identities and replaces fetch before SDK import/construction. Its synthetic, nonexpired OAuth credential exists only in memory; credential mutation/deletion is forbidden. Exactly one intercepted request to the fixed Codex endpoint is allowed. Real fetch is never retained/called, and there is no API-key/model/provider fallback, login or refresh in this slice.

The built-in request converter must transmit the declared `probe` tool and, on the second action, the actual correlated native tool result. Synthetic SSE first requests `probe({})`; the native loop executes the controller's side-effect-free test callback once. A separate admitted model action must receive and echo that exact Unicode result. The child never executes tools, opens native SQLite or runs a second agent loop.

An explicit test-only alias maps fixed provider/model/API metadata between the existing offline protocol and the built-in Codex route. Call IDs, tool results, content and signatures remain unchanged; unknown/unsupported event fields still fail the existing validators. The controller/native production provider guard remains **faux-only**. This alias is not permission to register a live provider.

Existing limits remain: one 10-second child lifetime per stream, controller-owned allowance/action cancellation, 64 KiB wire lines, 1 MiB aggregate transport, 1,024 frames and validated terminals. The parent withholds terminal success until clean child closure and owned-home disposal; native drainage precedes receipt/capacity release. These are trusted-host test controls, not a network sandbox or a server-enforced output-token guarantee.

## Verified outcomes

- Two admitted streams and one native probe result survive SQLite reopen with no replay.
- Pause inside the admitted tool preserves its result and prevents the next model action. Reopen stays paused; Continue spends no paused time, retains the same attempt/repair count and the exact 25 ms synthetic charge.
- HTTP denial, truncated SSE and an unconfigured tool park as `model-action-failed`, with no tool effects or automatic replay/fallback. Partial streaming never authorizes a tool.
- Cancellation before dispatch and at stream start rejects only after helper reaping/home removal. File profiles are rejected without entering their ownership boundary.
- Synthetic credential/account markers do not enter the operator projection.

TDD retains the initial five failing composition tests and the separate profile-boundary RED. The focused eight-test suite passes. Full `npm run verify:all` exits **0**, with **2,232 Node and 30 Rust tests passing**, no failures/cancellations/skipped Node tests or ignored Rust tests; lint, formatting, type/syntax checks and native compilation pass. Existing Rust dependency future-incompatibility notices remain. Raw logs/status are under `.audit/pi-native-codex/`.
