# Pi-owned inference compatibility design

## Scope and decision

After the [successful RPC feasibility experiment](pi-runtime-prototype.md), the operator approves option A's bounded offline investigation, not runtime replacement. Keep the existing controller, Pi Durable 1.3.0 case files and container-only execution authority. The [SDK characterization](#offline-sdk-seam-characterization), [bounded context/event transport](#validated-offline-contextevent-transport) and [caller-control transport prerequisite](#caller-controlled-offline-stream-lifecycle) pass; the overall compatibility experiment remains incomplete. No production architecture change, dependency upgrade, real credential access or further inference is authorized. [ADR 0005](adr/0005-retain-durable-inference-seam.md) accepts this investigation scope only.

The earlier design/review checkpoint proposed this experiment; the subsequent explicit “yes continue implementing the next step” supplies approval to start offline implementation. The real prototype proves a CLI-managed text turn only. It does not prove that the SDK route below has equivalent authentication, policy eligibility or tool behavior.

## Alternatives grounded in this checkout

| Option | Transcript and agent loop | Trade-off and disposition |
|---|---|---|
| **A — Keep Pi Durable; Pi-owned stream-only adapter** | Native SQLite remains the only durable conversation. Pi Durable remains the only agent loop; an isolated, trusted helper uses Pi's exported `ModelRuntime.streamSimple`, not `AgentSession.prompt`. | Smallest change to existing controller/tool/recovery contracts. Requires a new bounded transport and explicit 1.3.0/1.4.0 transcript/event compatibility checks. **Recommended for offline investigation, not proven or enabled.** |
| **B — Adopt the coding-agent runtime** | `AgentSession`/`SessionManager` would own the conversation/loop instead of Pi Durable. | Closest to the tested CLI authentication path, but requires replacing native conversation/task/document integration, controller dispatch hooks, crash recovery and expiry. | **RPC `prompt` masquerading as an A provider** | Pi Durable and the child each own an agent loop/context. | Reject. ## Proposed A contract

This is a design contract, not an implemented interface or a finding that existing recovery is atomic.

- **One owner:** the catalogue still owns admission, issue ownership, phase/control versions, action intent, active-work budget and receipts. Native case SQLite owns conversation/tasks/documents. The helper has no case database, durable transcript, session tree, tool executor or workflow authority. It receives the exact current native model context for each request; it never reconstructs context from a second history.
- **Small interface:** one active stream per admitted model action, plus cancellation/close. The request correlates case/action/epoch, fixed physical provider/model/API/endpoint, bounded transcript and explicitly permitted generation settings. It returns correlated normalized assistant events and one terminal message. Do not expose RPC shell/session commands, provider routing, credential operations, arbitrary headers/environment/API keys, custom endpoints, callbacks or extension loading through this interface. Reject virtual models and provider/model switching.
- **Version conversion:** validate both directions at runtime; do not cast 1.4.0 values into 1.3.0 types. Preserve ordered system/user/assistant/tool-result messages, tool definitions, call IDs/arguments, thinking/signature content required by the provider, usage and terminal/error reasons. Reject unsupported shapes/modalities rather than dropping them or flattening them into prose. The provider's actual terminal event is required; EOF, partial deltas and process exit are not successful completion.
- **Tools:** structured tool calls are returned as data to Pi Durable; the helper never executes them. Native registered tools must still obtain separate controller admission and use existing trusted check/workspace/worker paths. Unknown tools, hostile paths/arguments and stale action/revision evidence cannot authorize host filesystem, shell, Docker or network operations. Existing `run_check` chooses a configured check, not a model-supplied command. General source-edit tooling is separate unimplemented work, not granted here.
- **Auth and configuration:** any later live helper must let supported Pi code resolve/refresh its own OAuth internally, with no token export/import or credential fields in the transport, case data or diagnostics. Never call `getAuth` to extract a credential for Eitri. Require OAuth-only metadata for the fixed physical route; remove ambient provider keys and disallow fallback. Audit model/auth configuration and disable catalogue refresh, virtual routing and automatic activity explicitly. `ModelRuntime.create` defaults can read Pi configuration/credentials: the offline experiment must inject synthetic stores/configuration **before construction**, in a sanitized child environment, and must not open the user's Pi files. Running SDK code with real Pi storage is a separate live-auth decision, not covered by the earlier CLI turn.
- **Refresh ownership:** start with one serialized helper/active inference across cases; do not assume this serializes the operator's independent Pi processes or establishes cross-process refresh safety. Before real shared-store use, verify supported locking/refresh semantics or stop and agree an operational exclusion. No copying the user's store into Eitri or silently overwriting global settings.
- **Budgets and pause:** reuse catalogue model/tool admission, deadlines and active-work accounting. A pause request admits no next model or tool; an already admitted action may settle under the existing safe-boundary rules. Cancellation/deadline must abort the child stream and reap the child before acknowledging resource release; no child retry, compaction, queued prompt or second model call is allowed. Bound startup, each request, pipe bytes and teardown within the admitted allowance; never reset the allowance on helper restart.
- **Crash/checkpoint:** keep existing native result/checkpoint handling and catalogue reconciliation. They are not one atomic cross-store commit. A helper exit, controller crash or missing terminal/receipt must not synthesize success or replay a tool with uncertain effects. Charge an interrupted model action conservatively and preserve the current recover/queue-or-attention policy; a later permitted model attempt is new admitted work, not exactly-once delivery. Crash after provider acceptance can spend subscription quota even when no final message was saved. Late/duplicate events from an older action/epoch cannot settle newer work. Existing recovery tests are baseline evidence, not proof that A meets these rules.
- **History and expiry:** no helper JSONL file, raw pipe capture, content cache or permanent full-transcript catalogue receipt. Persist permitted messages/results only through native case storage, and artifact evidence through existing case-scoped stores. Reaping/closing must precede expiry; retain the existing case-only removal and compact duplicate-work guards. Global Pi credentials/configuration never become case payloads or expiry targets. Expiry is application deletion, not forensic erasure of OS backups or provider data.
- **Trust:** the helper/Pi library runs with its host user's permissions and is trusted code, not sandboxed by cwd, disabled tools or a pipe. Only configured worker execution has the existing container restrictions. No claim of Enterprise policy certification, network-payload audit, concurrent auth safety or tool-use entitlement follows from source inspection.

## Approved offline experiment acceptance criteria

Implement a **standalone offline compatibility probe**, not production wiring, against the reviewed installed 1.4.0 SDK and pinned 1.3.0 native types. Keep project dependencies/lockfile unchanged; pin/check the installed import and relevant source identities rather than following arbitrary global upgrades. All child/provider/auth transports use synthetic inputs and stores; no real login, default auth-store access, remote catalogue/inference, Docker, repository upload or hosted integration. Stop if the supported interface cannot satisfy the contract; do not patch Pi internals or fall back to RPC prompting.

Write failing tests first and retain runnable checks for:

1. A synthetic text → structured tool call → native tool result → next model response round trip, preserving exact context/call IDs without a second agent loop or helper tool execution; Unicode/thinking/usage and unsupported shape rejection.
2. Malformed/oversized/truncated streams, duplicate/late terminals, wrong action/epoch/model/endpoint and attempted route/key fallback; no partial success or raw diagnostic/credential leak.
3. Real subprocess cancellation/timeout/reaping, pause between model completion and tool admission, no automatic second dispatch/retry/compaction, and no renewed allowance on restart.
4. Native SQLite close/reopen and process crashes around admission, model terminal, native commit and receipt; retained conservative accounting and no uncertain tool replay. A fake-child protocol pass alone cannot prove these native contracts.
5. Two sequential cases with isolated context/IDs, eligible terminal-case expiry with no retained helper transcript, and no deletion of the other case or synthetic global auth store.
6. Synthetic OAuth refresh/auth errors/cancellation and same-helper refresh serialization, with poisoned ambient keys proving no fallback. This does not establish safety with independent real Pi clients.

Passing that slice permits another review/decision, **not** automatic production wiring or live tool-using inference. Any auth/permission change or real shared-credential/inference use needs explicit sign-off. Keep M4 open until a separately approved genuine controlled tool-using turn and the remaining integration checks pass.

## Offline SDK seam characterization

`npm run --silent probe:pi-stream` shows help without constructing a runtime. Explicit `-- --offline` runs only fixed synthetic fixtures in a subprocess, with a generated empty home/cwd, an allowlisted environment and no inherited provider keys or Node injection options. The probe checks `prototypes/pi-stream-source.json` before importing installed SDK code; unreviewed selected-source changes fail closed. The manifest pins relevant installed 1.4.0 SDK/AI and project 1.3.0 AI artifacts, **not the entire transitive installation**. The installed SDK at the recorded Homebrew path is an intentional local prerequisite for these compatibility tests; tests fail rather than skip on a different/missing installation. No project dependency or lockfile changes.

`ModelRuntime.create` receives synthetic in-memory credentials, `modelsPath: null`, `refreshOnCreate: false` and `allowModelNetwork: false` before construction; `PI_OFFLINE=1` disables automatic model-network activity. No default auth/model store is opened. A supported `registerNativeProvider` registration supplies an explicitly synthetic physical route (`eitri-offline/synthetic-text-tool`, `https://offline.invalid`), OAuth refresh and provider stream. This is **not** OpenAI's provider, OAuth implementation or transport. A forbidden-fetch sentinel checks for accidental fetch use; the trusted SDK/helper is not OS-network-sandboxed.

Two manually requested `streamSimple` calls preserve JSON-round-tripped, 1.3.0-typechecked system/user messages, tool definitions, Unicode, text/thinking/tool signatures, call IDs/arguments, usage and terminal reasons. The second receives the first assistant response and a **fixture tool result**, not a native tool invocation or SQLite commit. The installed 1.4.0 provider sees the exact context also normalized by project 1.3.0. One expired synthetic credential is refreshed internally and reused; the probe never calls `getAuth` to extract a token. No `AgentSession`, helper transcript, tool executor, retry/compaction loop or automatic second dispatch exists.

The initial characterization returned only fixed compact observations after assertions. The subsequent [transport increment](#validated-offline-contextevent-transport) replaces that child output with validated correlated event frames; the parent still returns only the same compact observations after exact fixture assertions, empty stderr and normal process completion. EOF/partial/extra/oversized output, diagnostics, altered messages and nonzero exit reject with fixed errors. Timeout/cancellation send SIGKILL and wait for child closure before removing the generated home. This is an offline kill/reap check, not cooperative live-provider cancellation or admission-budget accounting.

**Decision:** accept this first characterization as evidence that the exported stream-only SDK seam can be constructed without real Pi storage and can preserve these synthetic message fixtures. Do not equate it with a validated adapter. This deliberately smaller slice left all six acceptance criteria above open as a whole. The next subsection completes bounded runtime conversion and correlated transport for the explicit shared subset; it does not complete native tool/SQLite, control/accounting, expiry or built-in provider-auth parity. M4 remains open.

## Validated offline context/event transport

The same explicit `probe:pi-stream -- --offline` command now sends two fixed requests over a real subprocess stdin/stdout pipe. The child accepts **only** those exact synthetic requests and invokes `ModelRuntime.streamSimple` once per received request. After the first validated terminal, the parent explicitly sends the fixture tool result in the second request; the helper does not invoke a tool or autonomously follow up. Both sides use `prototypes/pi-stream-protocol.mjs`, not RPC or `AgentSession`. Production dispatch is unchanged.

Each request carries protocol version, case/action IDs, positive epoch, exact synthetic physical provider/model/API/endpoint, ordered context and an allowlisted `maxTokens` value (1–64). Every event repeats that identity and an exact increasing sequence. Runtime validation makes detached JSON copies of the reviewed common 1.3.0/1.4.0 shapes; it does not cast SDK values into native types or pack transcripts into text. System updates/sections/tool definitions/removals, Unicode, opaque text/thinking/tool signatures, call IDs/JSON arguments, fixture tool results/details, usage/costs and supported terminal metadata survive unchanged. Tool history must use declared tools, unique call IDs and exactly matching results before another request; terminal calls must name currently declared tools and not reuse prior IDs. Arguments remain data, not execution permission or a substitute for native tool-schema/controller admission.

The supported subset is deliberately narrow: text input/results, text/thinking/tool-call output and serial block events. Images/other modalities, custom roles, shorthand context, deferred results, namespaced/invalid-argument calls, constrained-sampling declarations, nested-call records, unknown fields and raw provider diagnostics/error bodies are rejected, not dropped. Supported `error`/`aborted` terminals retain their reason and validated assistant data, including usage, but never become a successful probe result; raw `errorMessage`/`diagnostics` payloads fail with a fixed error. This is not built-in provider error/auth compatibility. Mutable SDK partials are not assumed to be event-time snapshots; block ends and the actual matching terminal are authoritative. Returned events cannot mutate the receiver's retained result.

UTF-8 decoding is fatal, LF framing is strict (no blank/BOM/CRLF records), and truncated EOF is an error. Limits are 65,536 bytes including LF per request/frame, 1 MiB and 1,024 frames per pipe decoder, JSON depth 24, 128 transcript messages and 128 streamed blocks. Receivers additionally bound each action's bytes/events and accumulated deltas. Malformed values, unsupported shapes, invalid Unicode/numbers, lossy JSON values, prototype keys, wrong identity/sequence, mismatched deltas/block ends/terminal contents, duplicate/late terminals and post-error reuse fail closed. No raw pipe capture or diagnostic is retained. `length` remains a distinct terminal reason, not evidence of a complete remediation.

Only both complete expected streams **plus** clean EOF/exit 0 and empty stderr produce the fixed observation summary. Cancellation/timeout/protocol failure kills and reaps the child before removing its generated empty home. Source checks, sanitized environment, synthetic in-memory credentials/refresh, forbidden-fetch sentinel and no default user-store access remain in place. These are trusted helper/source controls, not an OS network sandbox or protection from malicious installed SDK code.

**Decision:** accept this bounded offline conversion/transport increment only. The [review and verification](evidence/pi-runtime/transport-review.md) record adversarial cases and actual subprocess checks. Next remain pause/deadline/restart accounting, real Pi Durable SQLite commit/crash/recovery and no uncertain tool replay, two-case isolation/expiry, and built-in synthetic auth failure/cancellation/serialization. No real Pi credentials, genuine inference, runtime migration, production wiring or M4 acceptance follows.

## Caller-controlled offline stream lifecycle

The next bounded prerequisite adds optional **trusted, synchronous caller callbacks** to the fixed offline probe: `control.admit(kind)` must return `undefined` or throw on denial; `control.remaining()` supplies a positive finite remaining allowance of at most 600,000 ms. A supplied incomplete control fails closed. These callbacks are not accepted from CLI/model/case/pipe data and are not a production controller adapter. Existing default/help/offline activation and the two exact synthetic SDK requests remain unchanged.

The parent requires admission before the first model request, before accepting the fixture tool-result handoff, and before the second model request. A denied boundary kills/reaps the helper without dispatching the next request. An already admitted final model stream may settle after a caller pause, without another admission. The `tool` boundary grants only the existing synthetic fixture data, **not native tool execution or a durable receipt**. A separate signal cancels active work; there is no helper retry, compaction or queued follow-up after failure.

A monotonic deadline begins at probe entry, not spawn, and is capped by both the existing 10-second probe limit and the caller's initial remaining allowance. Preparation and synchronous admission consume it. Every later reading can only tighten that ceiling, never extend it; the pipe timer is rearmed against the same ceiling after incoming chunks. Allowance/signal checks also guard dispatch, each complete frame and final child closure. Invalid/exhausted readings, expired terminals and callback failures return fixed errors, never raw controller/provider diagnostics. Failure still kills and awaits child closure before deleting only its generated empty home. Synchronous trusted callbacks and filesystem preparation cannot be forcibly interrupted while running; checks refuse subsequent dispatch when they return. This is not a hard real-time or host-code sandbox guarantee.

Tests use the actual installed ModelRuntime with synthetic provider/auth data for admission, pause, expiry and cancellation boundaries, plus uncooperative child fixtures for PID-reaping/time-ceiling checks. The restart test reopens a **synthetic caller-owned JSON deadline**: after expiry, another probe call cannot start a helper or receive a fresh default timeout. It demonstrates consuming a preserved caller allowance only; it does **not** prove catalogue recovery, native SQLite accounting, controller-crash behavior, repair-budget preservation or uncertain-tool replay prevention. No helper persistence/transcript or second budget owner is added.

**Decision:** accept this caller-control transport prerequisite and stop. The [five-axis author review](evidence/pi-runtime/control-review.md) records verification and the tightened-deadline regression. Actual controller/native pause/deadline/restart and SQLite crash/commit/receipt parity remain the next task, followed by two-case isolation/expiry and built-in synthetic auth checks. Keep production dispatch, real credentials/inference and M4 acceptance gated.
