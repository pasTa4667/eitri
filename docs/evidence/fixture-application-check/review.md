## Findings and applied feedback

- **Important — PNG reads were bounded only after allocation.** `worker/frozen-browser/application-driver.mjs:25` now checks regular/single-link/non-symlink identity and the 4 MiB size ceiling before reading, then requires the observed byte count to match. `test/fixture-application-driver.test.mjs` first fails for directory, symlink, hardlink, oversized and changed-size cases and passes after the fix. Host PNG decoding/integrity admission remains mandatory.
- **Important — complete command identity was not checked by application-result admission.** `scripts/profile-reconciliation/application.mjs:53` now requires exactly the protected unit/build/browser argument vectors as well as exits, signals, exact assertions, unit witness and compiled-response proof. The corruption matrix includes substituted commands, incomplete checks, skips/retries, unexpected failures and broken provenance. A claimed green verdict alone is insufficient.
- **Important — minimal child environment initially omitted the installed browser location.** Actual execution reports a missing Chromium executable, not a failing target. `worker/frozen-browser/application-driver.mjs:10` now supplies the fixed `/ms-playwright` location without inheriting the parent environment or downloading browsers. The subprocess test checks the entire environment, timeout and output ceiling, including exclusion of a parent protocol-nonce sentinel. Earlier failure remains retained in local diagnostics; it is not counted as successful validation.
- **Important — the application process tree accumulated orphaned browser descendants.** Actual repeated runtime checks expose crashes in the later fresh-context control and, in some attempts, oversized failure reports. `worker/frozen-browser/application-supervisor.py` now uses the existing kernel subreaper/wait facilities to reap adopted descendants while retaining the main harness exit. There is no PID/memory increase, sandbox bypass, seccomp change or new installed package. Three tests cover reaping past the main child, preserving failure, and refusing to start when subreaper setup fails. Actual final profile/cart runs both pass; each later outer census has 15 processes and one outer-browser zombie versus an earlier profile baseline's 26 processes and 12 zombies. No claim is made that this measures the application's peak live task count.
- **Important — existing documentation incorrectly excluded all source execution in Node.** `docs/frozen-browser.md` now states the narrow opt-in reviewed-byte exception and the worker-configuration compatibility limit. `docs/fixture-application-check.md` distinguishes bundled observations from separate typed unit/build receipts, the normal-view PNG from target-specific assertion results, and the outer containment census from earlier application-browser processes.
- **Suggestion — simplify trusted-asset acquisition.** The nested promise/continuation was replaced with one fixed bounded asset list and an explicit payload. No plugin/configuration framework or new dependency is introduced.
