## Five axes

- **Correctness:** `ModelRoute.drainModel` is memoized per admitted action and awaited on terminal and abort/error paths, before existing finish/receipt callbacks. Lifetime validation after disposal prevents a late terminal from renewing an allowance. Native close/reconcile await tracked guards for opted-in routes. Seven deterministic barrier cases cover deadline, deadline-plus-close, ordinary close, pause, reconcile, early terminal and rejected disposal. Assertions inspect actual catalogue action rows, queued-case status, zero tool effects, blocked replacement-controller admission, actual PID/home absence, SQLite reopen, exhausted allowances and stale pre-restart wakeups. Existing native tool-result and SIGKILL checks remain enabled.
- **Readability:** a small optional route method plus a set of active model guard promises; no provider factory, generic lifecycle framework, new store or duplicated agent loop. The drain promise is cached so a failed terminal check cannot call disposal twice. The test helper indexes its pending adapter promises by the already-admitted action ID and deletes them after drainage.
- **Architecture:** `src/controller.ts` only shares the route type; admission, accounting, scheduler, catalogue/native schemas and recovery policy are unchanged. Production `src/main.ts` still selects the existing scripted provider, and `src/native.ts:157` still refuses non-faux providers. The sole resource-owning implementation is the offline test adapter. Native tools and legacy routes without a disposal hook do not acquire a universal cleanup guarantee. No new runtime or transcript owner is selected.
- **Security:** the route method and cleanup/terminal barriers are trusted code, not model/CLI/pipe inputs. Existing strict source/framing/identity checks, empty generated home, allowlisted child environment and synthetic in-memory auth remain intact. The transport always attempts home removal after its barrier, even if the barrier throws, and sanitizes failures. The helper exposes fixed error events and rejects its drain on provider/cleanup failure. Adapters must never settle a drain with live execution resources; cleanup-attempt failure is not reported as cleanup success. No real credential access, network route, containment relaxation or dependency change occurs.
- **Performance:** one pending promise per active managed model action; entries are removed on settlement. No raw transcript/cache or extra subprocess is introduced. Streams retain existing framing/byte/time limits. A blocked trusted drain intentionally retains capacity and shutdown ownership rather than introducing an unsafe second timeout that claims release; callbacks/filesystem operations are not a hard-real-time sandbox.
