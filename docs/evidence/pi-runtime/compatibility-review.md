| Axis | Findings and disposition |
|---|---|
| Correctness | `docs/pi-runtime-compatibility.md:13–19,29,34`: RPC prompting is agent work, not a replacement provider stream. The recommendation instead names the exported stream-only SDK interface and requires lossless validated version conversion. Native recovery remains cross-store and conservatively accounted, not exactly-once provider delivery. No adapter compatibility is claimed from a text-only CLI pass. |
| Readability | `docs/adr/0005-retain-durable-inference-seam.md:2,7–9`: short rationale with **proposed** status; detailed contracts and falsifiable acceptance checks live in one linked design rather than another implementation plan. |
| Architecture | `docs/pi-runtime-compatibility.md:13–17,27–30`: one native transcript/agent loop and one catalogue dispatch authority. No new SDK dependency, production helper, custom OAuth, schema or session-store migration. Full-runtime adoption is an explicit deferred alternative, not silently selected. |
| Security | **Important approval distinction, addressed:** `docs/pi-runtime-compatibility.md:5–7,31–32,40,51` explicitly prohibits treating the prior CLI turn as permission for SDK shared-store access. Offline construction must inject synthetic stores/configuration before defaults can open user files. No raw credential extraction or ambient key fallback; global refresh concurrency and actual Enterprise eligibility remain later gates. `:30,36` distinguish container-restricted tools from the trusted host helper; no sandbox claim based on a pipe or cwd. |
| Performance | `docs/pi-runtime-compatibility.md:28,32–35,45–48`: one active request, serialized helper, bounded pipes/startup/stream/teardown, child reaping before release/expiry, no retries or growing shadow history. These are experiment acceptance requirements, not measured throughput or implemented resource guarantees. No optimization or performance improvement is claimed. |
