## Five-axis disposition

- **Correctness:** the native fixture declarations are typechecked against project Pi AI 1.3.0 (`prototypes/pi-stream-fixtures.ts`; `test/pi-stream-types.test.ts:11–20`). The actual installed ModelRuntime 1.4.0 receives/returns the JSON-round-tripped structured fixtures, preserving signatures, Unicode, IDs, usage and terminal reasons. A fixed assertion checks its provider context against the project normalizer (`prototypes/pi-stream-child.mjs:88`). The synthetic tool result is data only. Parent tests reject empty/partial/extra/oversized/diagnostic/nonzero outcomes; this tests the **compact result framing**, not hostile provider-stream conversion.
- **Readability:** separate small files for the one-shot wrapper, fixed SDK fixture exercise and native-typed data; no generic provider framework, conversion abstraction, session tree or new dependency. Fixed errors and compact observations avoid raw diagnostic retention.
- **Architecture:** no production `src/`, worker, catalogue/case schema, credential module or operator changes. Only the standalone opt-in command imports the installed SDK in its generated-home child. `ModelRuntime.streamSimple`, not RPC `prompt`/`AgentSession`, owns each raw synthetic stream; no extra agent loop or tool executor exists.
- **Security:** `prototypes/pi-stream.mjs:47–64` supplies a fresh allowlisted child environment, excluding ambient provider keys and Node injection settings; the child verifies it, allowing only macOS's injected non-secret locale field (`prototypes/pi-stream-child.mjs:10–28`). Storage/configuration are supplied before runtime construction (`:61–67`), with no default user-store opening, login or real refresh/inference. Supported Pi code refreshes one synthetic credential internally; the probe never exports real auth or invokes `getAuth`. The fetch sentinel and reviewed source are not an OS network sandbox; trusted SDK code retains host permissions. The `childPath` injection seam is trusted test-only, never a CLI/model/case option.
- **Performance:** fixed two-call inputs, no retained helper history, 4-KiB output cap, 10-second maximum child timeout, SIGKILL/reaping before cleanup and no retry/automatic second dispatch. These bound this fixture runner, not controller admission/restart accounting, live-provider cancellation or throughput. Tests use temporary stores/files only.

**Verdict:** no unresolved Critical/Important defect in this first offline characterization. Accept it as a small save point, not acceptance of the overall compatibility experiment or M4. Next is validated bounded context/event conversion and correlated transport, followed by native crash/budget/expiry and provider-auth parity checks. Real Pi credential access, live tool-using inference, production wiring and runtime migration still require separate approval.
